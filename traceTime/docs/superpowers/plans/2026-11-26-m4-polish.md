# traceTime M4（桌面打磨）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付异常恢复、位置记忆、原生毛玻璃/半透明/不透明背景降级，以及小组件闲置淡化；不影响历史窗口和设置窗口。

**Architecture:** Rust 继续拥有启动恢复、窗口位置和原生背景策略。SQLite settings 记录主窗口位置与背景模式；启动时先恢复数据状态，再恢复窗口几何并应用平台可用背景。前端只负责闲置交互检测、背景 class 和紧凑 UI；原生 vibrancy/acrylic/blur 由 Rust 调用 `window-vibrancy` 并返回实际生效模式。

**Tech Stack:** Tauri 2、Svelte 5、rusqlite、window-vibrancy。

**Spec:** `docs/2026-11-26-tracetime-design.md`（第 3.1/7/10 节）

## Global Constraints

- M3 已交付任务级超时通知静音；本计划不重复实现。
- running 任务重启恢复时宁可少记工作：在最新 started/resumed 事件到恢复时刻之间追加 `anomaly` 段，并把任务转为 paused；不把未知崩溃期计入净耗时。
- 恢复写路径事务化，只追加段/事件；同一任务重复恢复必须幂等；paused 任务原样保留。
- 位置 key 为 `widget_position_x` / `widget_position_y`，保存物理像素整数；没有有效位置时不设置。
- 背景 key 为 `background_mode`，可选 `glass`（默认）、`translucent`、`opaque`；`glass` 平台不支持时实际降级为 `translucent`。
- 全透明不采用；文字底色必须保持可读。
- 主窗口闲置约 10 秒淡化到约 20% 不透明度，鼠标悬停立即恢复；暂停菜单、切换表单和错误状态不得因淡化不可用。
- 设置/历史窗口不应用闲置淡化。
- 每个任务运行 `pnpm test && pnpm check && pnpm build`，涉及 Rust 时运行 `cd src-tauri && cargo test`。

**Interfaces:**
- Produces:
  - `Tracker::recover_running_tasks(recovered_at: chrono::DateTime<Utc>) -> Result<Vec<TaskDto>, String>`
  - 生产启动调用 `recover_running_tasks(Utc::now())`
  - `Tracker::set_widget_position(x: i32, y: i32) -> Result<(), String>`
  - `Tracker::widget_position() -> Result<Option<(i32, i32)>, String>`
  - IPC `set_widget_position`；生产 setup 直接恢复位置，不需要前端命令。

- [ ] **Step 1: 先写失败测试**
  - 构造 running 任务并把 started 事件改为过去时间，调用恢复；断言 status=paused、新 anomaly 段不增加 work 净耗时、事件包含 `paused(reason=anomaly)` 和 `anomaly_recovered`、再次调用不重复追加。
  - 构造 paused 任务，调用恢复；断言任务和事件无变化。
  - `set_widget_position(120, -80)` 后 `widget_position()` 返回 `(120,-80)`；空库返回 None；非法值在 IPC 层拒绝。

- [ ] **Step 2: 实现**
  - running 恢复：找最新 started/resumed 事件；插入 `kind='anomaly'` 段（start 到 recovered_at，负区间截为 0）；追加 `paused` detail `{"reason":"anomaly"}` 与 `anomaly_recovered`；更新 status=paused；事务提交。
  - 幂等：先检查是否存在该任务的 `anomaly_recovered` 事件。
  - 位置使用 settings KV；`set_widget_position` IPC 校验 `i32::MIN..=i32::MAX` 即可，坐标可为负。
  - main setup 中读取位置，仅当 `Some` 时对 main 窗口调用 `set_position(PhysicalPosition)`。
  - main 的 `on_window_event(Moved)` 保存最新物理坐标；重复写 SQLite 可接受，但不阻塞 UI 线程事件分发。

### Task 2: 原生毛玻璃降级与背景模式

**Files:**
- Modify: `src-tauri/Cargo.toml`
- Modify: `src-tauri/tauri.conf.json`
- Modify: `src-tauri/src/main.rs`
- Modify: `src-tauri/src/commands.rs`
- Modify: `src-tauri/src/tracker.rs`
- Modify: `src/App.svelte`
- Modify: `src/components/SettingsView.svelte`
- Modify: `src/lib/settings.ts`
- Test: `tests/settings.test.ts`、`src-tauri/src/tracker.rs`

**Interfaces:**
- Produces:
  - IPC `apply_background_mode(mode: String) -> R<BackgroundModeResult>`
  - `BackgroundModeResult { requested: 'glass'|'translucent'|'opaque', effective: 'glass'|'translucent'|'opaque' }`
  - 设置页“背景”三选一；前端主壳根据 effective 应用 `glass/translucent/opaque` class。

- [ ] **Step 1: 先写失败测试**
  - Tracker/API 测试：非法 mode 返回错误；合法值 roundtrip；缺省 background mode 为 `glass`。
  - 前端 helper 测试：`normalizeBackgroundMode`、`backgroundClass(effective)`、不支持平台时 requested=glass 但 effective=translucent 的映射。

- [ ] **Step 2: 实现**
  - `tauri.conf.json` main window：`transparent: true`、`decorations: false`、`shadow: true`；历史/设置窗口保持不透明。
  - main widget 加 `data-tauri-drag-region` 顶部安全拖拽区，控件区域不拖拽。
  - Rust 按平台尝试 `window-vibrancy`：macOS vibrancy、Windows acrylic/Mica、Linux blur；任一失败返回 effective=`translucent`。
  - `translucent` 使用主窗口透明 + 深色约 78% CSS 底色；`opaque` 使用深色不透明底色。
  - 应用启动调用默认/已保存模式；SettingsView 保存后调用 `apply_background_mode` 并显示实际效果。
  - WebView `html/body` 背景透明，避免遮住原生 blur。

- [ ] **Step 3: 验证提交**
Run: `pnpm test && pnpm check && pnpm build && cd src-tauri && cargo test`
Expected: 全绿；macOS dev 运行时人工检查 glass/translucent/opaque 三态。

